## 4. 为什么左右各自 LQR 会产生差速问题

模型的 6 个状态描述同步纵向运动，没有偏航状态。原代码却用每侧自己的 theta、x、v 计算两轮输出，同时另有防劈叉环约束两腿，不能据此认为两侧各自闭环就组成了稳定的转向控制。

当前 K 的轮速度项是：

```text
T_model_velocity = -K[0][3]*v = +1.6995*v
```

只考察速度差的贡献，若右轮比左轮更快向后，这一项会让右轮得到更大的向后模型力矩。这里说的是差速贡献，**不能据此判定完整纵向 LQR 的速度符号错误**；纵向稳定依赖腿角和机体角的耦合反馈。

新实现只计算一次纵向 LQR：

```text
theta_common     = (theta_L + theta_R)/2
theta_dot_common = (theta_dot_L + theta_dot_R)/2
v_common         = (v_L + v_R)/2
x_common        += v_common * measured_dt

T_common, Tp_common = -K * common_error
```

单侧 K 的结果分别施加到左右两侧，不再除以二。左右 `x_m` 使用同一个积分；左右 `theta_rad`、`v_m_s` 保留各侧读数供观察。原独立积分产生的差速位置误差不再进入轮输出。

速度差由独立阻尼处理：

```text
delta_v = v_R - v_L
T_diff  = clamp(1.0*delta_v, +/-0.8 N*m)
T_L_model = clamp(T_common + T_diff, +/-5 N*m)
T_R_model = clamp(T_common - T_diff, +/-5 N*m)
```

在未限幅时，差速项对轮的功率为 `-Kd*(v_R-v_L)^2/R`，方向是耗散。当前仅加速度阻尼，没有加入航向角位置环；静止后不会主动回到某一绝对航向。实际打滑、轮速观测偏差和左右执行能力不一致仍会影响效果。

防劈叉保留原 Kp，新增速度阻尼：

```text
S = clamp(Kp*(theta_rel_L-theta_rel_R)
        + Kd*(theta_rel_dot_L-theta_rel_dot_R), +/-10000 N*mm)
Tp_L_VMC = Tp_common - S
Tp_R_VMC = Tp_common + S
Kp = 30000 N*mm/rad
Kd = 2000 N*mm*s/rad
```

左右相对摆动的这一项也沿阻尼方向作用。它不改变公共髋力矩的正向。

## 5. 时序与腿速

原 INS 任务把周期值 1 传给 `osDelayUntil`。该 API 接受绝对唤醒时刻，不是延时长度；系统运行超过第 1 tick 后，这个时刻已经过去，不能形成原本想要的 1 ms 调度。现在累加下一唤醒时刻。

两腿由一个任务读取 INS、四台腿电机反馈和两轮 RPM，计算并发送本周期六台电机的指令。保留上电等待 5 s；四台腿电机统一初始化、重试使能。所有腿电机在线、已使能、无故障、反馈未超时且两腿 FK/J 有效时才进入控制。保留 `RLeg_task` 函数用于源码兼容，RTOS 不再创建第二个腿控制任务。

控制目标周期仍为 1 ms，积分使用 DWT 测得的实际 dt；`balance_control_dt_s` 和 `balance_control_overruns` 可检查实际运行情况。修正后的时序需要实板验证，离线 ARM 测试没有模拟 RTOS 和 CAN 总线负载。

腿速改为用电机速度反馈和雅可比计算：

```text
B_dot = J * [qa_dot, qb_dot]^T
L_t_dot = (B dot B_dot) / L_t
theta_rel_dot = (B_x*B_dot_y - B_y*B_dot_x) / L_t^2
```

这避免将“本周期 CAN 位置未更新”误判为零腿速，再在下一周期产生差分尖峰。实际速度量化、反馈延迟和雅可比奇异仍受原电机/FK条件限制。

`y=-0.065042 m` 和 `THETA_E_RAD=-0.065042 rad` 数字相同不构成换算关系。上述 CLI 物理参数的理论平衡角是 +0.04554234565 rad。传感器坐标的目标可以包含零点偏置，但需要真实几何/稳态条件支持；若稳态测量时仍有支撑或持续轮力矩，它不等于无输入平衡点。

**轮速观测仍有近似。** C620 的速度反馈来自电机转子相对定子的运动。定子随真实串联腿运动时，需要将其真实世界角速度加回，才能严格得到轮心纯滚动车速。本次只保留已验证的 RPM 比例和正负号，没有把等效 AB/CB 的角速度当成实物定子角速度。

```text
v_wheel_center = v_encoder_relative + R*omega_real_stator
```

在固定腿内构型时，真实下腿与等效整体腿共同转动；快速伸缩时还涉及腿内相对运动，不能从“轮心在 B”这一点的位置就确定定子姿态映射。本模型 x 是轮心位置，所以不能把参考工程的髋部平移项 `L_t*cos(theta)*theta_dot` 直接加进来。

70 N 是固件前馈设置，不是力传感器测量值。模型的 `(M+m_p)*g` 约 87.23 N；本次没有据一帧 `F_axis_N<0` 就把前馈改大。`F_axis_N` 是虚拟指令，可能由长度超调、阻尼和横滚项共同导致，不能直接当作地面支撑力。新增 `F_spring_N`、`F_gravity_N` 便于分开检查。

共享纵向 LQR 去掉了左右腿角/位置/速度各自生成差速的通道；独立阻尼减小速度差，同步计算和防劈叉速度阻尼也一起改善左右一致性。无法只凭一次实验区分这几项各自贡献，但本帧的差速指令确实沿减小两轮速度差的方向。

### 11.3 已确认的执行问题：独立截断把髋输出切没

本帧公共髋请求为 11.816 N·m，防劈叉之后左右请求约 11.677/11.956 N·m；轴向力请求均被限到 250 N。四个关节发送指令却是：

```text
左侧原始命令：       [+20, -20] N*m
右侧原始命令：       [-20, +20] N*m
右侧换到统一坐标：   [+20, -20] N*m
```

对当前共轴等效运动学，两输入角同时增加 dγ，末端 B 绕 O 同时转过 dγ，长度不变。虚功为：

```text
(tau_a + tau_b)*d_gamma = Tp*d_gamma
Tp_sent = tau_a + tau_b
```

因此本帧限幅后的发送髋力矩为左右各 0 N·m，虽然 LQR 请求约 11.8 N·m。反馈合成也接近零：左约 −0.264 N·m、右约 −0.053 N·m。瞬态反馈与命令有延迟，这些数值不能用来判定电机的长期最大能力，但发送指令的抵消本身是确定的。

原代码先把伸腿力和髋力矩映射到两关节，再把两关节各自截到 ±20 N·m。伸腿力较大时，这种操作会保留一对相反关节力矩，丢掉公共髋平衡分量。于是髋部没有执行模型需要的纠正，而轮子还在接收后退力矩；原来 A−BK 的稳定性结论不适用于这种被严重改写的执行输入。

### 11.4 修正：先保留髋分量，再分配剩余能力给伸腿力

`VMC_TorqueAllocate` 用实际 J 将极坐标指令分成两部分：

```text
tau_i = a_i*F_axis + b_i*Tp
a_i = (J_i dot e)/1000       # m
b_i = (J_i dot n)/L_t_mm     # 无量纲
```

先检查髋分量自身是否能在 ±20 N·m 内实现；若不能，按同一比例缩小该髋分量。固定可实现的髋力矩，再求两个关节约束允许的轴向力区间，将轴向力请求限制到区间中。保留最终逐电机限幅作为数值保护。

这保持原 K、方向、腿长 Kp/Kd、目标长度和 20 N·m 上限；改变的是超限时如何分配有限关节能力。轴向力不足时会减小伸腿力，可能让起身变慢。原本在能力范围内的指令保持不变。这不是增加电机的物理能力，也不是把分配出的力当成实际支撑力测量。

离线测试已复现“大伸腿力＋12 N·m 髋请求”的情形：原独立截断合计为 0，新分配保留约 12 N·m，并使两个关节都在原上限内；还验证了髋请求本身超限的处理。

此次修改文件为 `Algorithm/VMC.c/h`、`Tasks/Leg_Tasks.c`、`Matlab/tests/control_pair_test.c` 和本文；备份位于 `tmp/torque_allocation_20261011_before/`。完整工程已编译链接成功，未烧录。

### 12.3 纠正位移状态限幅

此前把公共位移夹在 ±0.3 m，是前一次排查时添加的状态限制，与动力学状态定义不一致：

```text
旧实现：x_next = clamp(x + v*dt, -0.3, +0.3)
新实现：x_next = x + v*dt
控制复位时：x = 0
```

x 到 −0.3 m 后继续后退，旧状态不再变化。例如持续 −0.7199 m/s 再走 1 s，累计位移应约 −1.0199 m，旧状态仍为 −0.3 m。位置反馈被冻结，且不满足 A 矩阵第三行 x_dot=v；理想闭环极点不能证明这种截断状态后的控制稳定。

现在恢复积分，让完整位置误差继续进入耦合 LQR。它不是单独增加一个反向刹车项，轮与髋仍由两行 K 一起纠正。原轮力矩 ±5 N·m、髋请求 ±13 N·m、关节 ±20 N·m 输出约束全部保留。未修改 K、THETA_E_RAD 或反馈/力矩方向。

此修改消除了确定的实现错误，但不能证明角度零点、轮矩比例、定子运动补偿或电机执行问题已解决。
